Install guide

From a new Windows machine: install the Azure CLI, sign in, create terraform.tfvars, run infra/terraform/deploy.ps1, then connect AI Foundry to the Function App. Every step below matches a script in this repo.

The environment already built is resource group kiwi-ocr-rg-stmt03, Foundry account kiwi-ocr-aiservices-stmt03, project kiwi-ocr-proj-stmt03, function kiwi-ocr-func-stmt03. For a new environment, change unique_suffix and the names follow.

The classification model must be 5.4. gpt-4o leaves salary and obvious merchants as unclear. Terraform still creates the AIServices deployment under the name gpt-4o (infra/terraform/main.tf hardcodes that name). After apply, set the Foundry agent's model to 5.4. Do not leave it on gpt-4o.

1. Install local tools

Open PowerShell. After these three finish, close the window and open a new one. Otherwise az and terraform are not on PATH yet.

winget install --exact --id Microsoft.AzureCLI
winget install --exact --id Hashicorp.Terraform
winget install --exact --id OpenJS.NodeJS.LTS

Then install Azure Functions Core Tools 4. A plain npm install -g on Windows often fails with EPERM (permission denied). Add --unsafe-perm true:

npm install -g azure-functions-core-tools@4 --unsafe-perm true

Confirm all four print a version. Terraform must be 1.5 or newer. Core Tools must be 4.x.

az version
terraform version
node --version
func --version

2. Sign in and pick the subscription

az login
az account set --subscription "your-subscription-name"
az account show --query "{name:name, id:id}" --output table

deploy.ps1 runs az account show and exports ARM_SUBSCRIPTION_ID and ARM_TENANT_ID. The azurerm 4.x provider fails without them. Do not commit a subscription id.

If the script says Not authenticated to Azure. Run: az login, run the login above and start the script again.

3. Go to the script directory

Every deploy command runs from infra/terraform, not the repo root.

cd D:\workspace\kiwi-knowledge-bill-ocr\infra\terraform

The script is deploy.ps1. Foundry follow-up text is printed by configure-foundry.ps1 in the same folder, invoked as deploy.ps1 -Action configure-foundry.

4. Create terraform.tfvars

Nothing in the repo writes terraform.tfvars for you. deploy.ps1 only adds -var-file=terraform.tfvars when that file already exists. Without it, Terraform uses the defaults in variables.tf, and the names and region will be wrong.

Copy the example, then edit it. The copy is gitignored. Do not commit it.

Copy-Item terraform.tfvars.example terraform.tfvars

Open infra/terraform/terraform.tfvars and set at least these:

VariableValue used for stmt03What it does
project_namekiwi-ocrName prefix
unique_suffixstmt03Empty means a random suffix. Use 4–8 characters to keep the names stable
locationaustraliaeastRegion
environmentdevTag
create_foundry_aiservicestrueCreates the Foundry project visible at ai.azure.com
create_classic_foundry_hubfalseThe classic hub does not show in the new portal. Leave this off

With suffix stmt03, Terraform names the resources:

  • Resource group kiwi-ocr-rg-stmt03
  • Function kiwi-ocr-func-stmt03
  • Foundry account kiwi-ocr-aiservices-stmt03
  • Project kiwi-ocr-proj-stmt03
  • Storage account kiwiocrsastmt03 (lowercase, hyphens removed)

Do not run apply against a subscription that is already in use unless this is the stack you mean to create or update. deploy.ps1 -Action apply creates real resources and incurs cost.

5. Run deploy.ps1 in this order

Stay in infra/terraform.

.\deploy.ps1 -Action init
.\deploy.ps1 -Action validate
.\deploy.ps1 -Action plan
.\deploy.ps1 -Action apply
.\deploy.ps1 -Action deploy-functions
.\deploy.ps1 -Action generate-openapi
.\deploy.ps1 -Action configure-foundry
.\deploy.ps1 -Action outputs
  1. init only initializes local state (terraform init -backend=false).
  2. validate and plan create nothing. Read the plan and confirm the function name is kiwi-ocr-func-<your-suffix>.
  3. apply asks again before it creates anything.
  4. deploy-functions publishes from the repo's function_app directory with func azure functionapp publish <function-name> --python. The remote build uses Python 3.11. A newer local Python is only a warning.
  5. generate-openapi reads the function URL from Terraform output and writes foundry/openapi-servicing-<suffix>.json. Do not commit that file. The template foundry/openapi-servicing.json still points at the old vikas host. Do not upload the template to Foundry.
  6. configure-foundry prints the portal steps in the terminal. It may print the function key on screen. Do not paste that output into chat, email, or the repo.

6. Commands when a step says permission denied

EPERM while installing Core Tools

Same command as step 1. The flag is --unsafe-perm true:

npm install -g azure-functions-core-tools@4 --unsafe-perm true

Azure returns AuthorizationFailed

terraform apply or az functionapp keys list returns AuthorizationFailed when the signed-in account is not Contributor on the subscription. You usually cannot grant that role to yourself. A subscription Owner or User Access Administrator runs it. First get your object id:

az ad signed-in-user show --query id --output tsv

The Owner, in their own signed-in session, runs this. Replace both placeholders. Do not commit them:

az role assignment create --assignee "<object id from above>" --role "Contributor" --scope "/subscriptions/<subscription id>"

Role assignment can take a few minutes. Then run az account set again and resume at the step that failed. Do not start a second stack from init.

To let the Function App call Document Intelligence with a managed identity, do not run a role command by hand. Set use_managed_identity = true in terraform.tfvars and run .\deploy.ps1 -Action apply. The az role assignment create --role "Cognitive Services User" snippet in docs/AZURE_DEPLOYMENT_GUIDE.md is the same step written out by hand. Terraform does it when that flag is on.

7. Connect Foundry to the Function App

Terraform cannot do this part. The portal is https://ai.azure.com.

  1. Open project kiwi-ocr-proj-stmt03 (or kiwi-ocr-proj-<suffix> for a new environment). The resources already exist. Do not create another hub.
  2. Create an agent. Set the model to 5.4. Do not use gpt-4o.
  3. Turn Code Interpreter off.
  4. Add tool → OpenAPI spec. Upload the file from step 5, foundry/openapi-servicing-<suffix>.json. For stmt03, servers[0].url must be https://kiwi-ocr-func-stmt03.azurewebsites.net/api. Do not upload foundry/openapi-servicing.json from the repo.
  5. Create a project connection. The connection name is function-app-key (a label only). The custom header name must be x-functions-key, matching securitySchemes.functionsKey in the OpenAPI file. The value is the function Host key named default, not _master. In the portal: Function App → App keys → Host keys → default. Do not paste that value into chat or into the OpenAPI file.
  6. Select that connection on the OpenAPI tool. Do not paste the key into the tool a second time.
  7. Paste the whole of foundry/PASTE-THIS-INTO-FOUNDRY-AGENT-INSTRUCTIONS.txt into the agent's Instructions. foundry/prompt-foundry-v2.md is the same text for people editing the prompt. Do not upload the markdown file.
  8. Start a new Foundry chat before running a statement. An old chat keeps the previous model and the previous instructions.

Do not use the portal Functions list to decide whether publish worked. That page shows Runtime version Error and an empty list. Without a key: GET https://kiwi-ocr-func-stmt03.azurewebsites.net/ returns 200, and POST /api/compute_summary returns 401. That means the code and the route are there.

8. Publish again after a code change

When only function code changed and the infrastructure did not, skip apply:

cd D:\workspace\kiwi-knowledge-bill-ocr\infra\terraform
.\deploy.ps1 -Action deploy-functions

When only the prompt changed, do not publish the function. Open a new Foundry chat and paste PASTE-THIS-INTO-FOUNDRY-AGENT-INSTRUCTIONS.txt again.
